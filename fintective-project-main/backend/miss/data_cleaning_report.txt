CAVEAT - read before trusting this for training:
  The "same_company_diff_candidate" bucket (16 bill numbers) was resolved by keeping
  only the most recent row per bill number. This is a safe default to avoid double-
  counting revenue, but it's an assumption: if these were actually two genuinely
  separate placements that happened to get the same bill number typed in by mistake,
  one real placement's revenue is being silently dropped rather than fixed. Same
  caveat applies to "same_deal_revised_amount" (15 bill numbers) - assumed the latest
  entry is the corrected one, which is usually but not certainly true.
  Worth a spot-check against Tally/physical invoices before fully trusting revenue
  totals derived from this exact resolution.
